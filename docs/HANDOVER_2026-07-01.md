## 1. What City Battle is

A tactical mecha-artillery wargame — *"Rule the Waves, on land"*: artillery "crab-mecha" walking
warships fight across **real topographic 3-D city terrain (Sydney)**. Two runtimes share one
canonical map JSON:

- **Unity 6 game** — the deterministic simulation + full systems (combat, comms/intel, command,
  campaign). EditMode tests: **89/89 passing**.
- **Web hub (Three.js)** — a browser-playable tactical-map demo + designer/tech/command/tutorial
  pages. **This sprint was almost entirely the web tactical map.**

The two headline "critically interesting" pillars: **topographic 3-D Sydney maps** and **artillery
mechanics** (LOS, dead-space/defilade, direct/indirect/high-angle ballistics, immunity/threat bands).

## 3. What the web tactical map does today (playable)

Pick a city + scenario → place move/hold/attack flags (+ waypoints) → assign flagship → formations
& best-position → friendly **and maneuvering enemy AI** path, engage with **real ballistic LOS** and
knockouts → objective resolution (hold-timer / eliminate / escort) with VICTORY/DEFEAT banner →
targeting computer + **maths fire-solution panel** (muzzle vel, QE, angle of fall, ToF, apex, charge
zone, hit zone, multi-gun selector, "CANNOT REACH") → parabolic fire arcs (visible even for
unselected units) → **combat POV inset** down the firing LOS → **auto-pause** on chosen events +
lingering event popups → **Order-of-Battle unit list (U)** with spotted-enemy eye/crosshair intel →
synth SFX + decaying/expandable combat log → pause/play (SPACE) at ½×–8× speed.

Map/analysis overlays: real Sydney terrain (res 513), **true N-E-S-W compass**, fog-of-war viewshed,
comms mesh (LOS relay), ballistic dead-space, slope/trafficability, **real OSM suburb boundary
polygons with 4-colour territory infill**, 11k roads, 40k buildings, weather panel, **red THREAT
band** (independent toggle), **draggable panels**, **title menu + hotkeys**.

## 5. Reflection — honest assessment

**Strengths of where it landed:**
- The tactical map is genuinely **playable and readable** now — you can fight a winnable battle, see
  *why* a shot can/can't land, watch trajectories, and manage a force from a spreadsheet.
- The **artillery/topography pillars are real**, not cosmetic: LOS, defilade, trajectory choice,
  spotter-dependent indirect fire, and threat/immunity bands all interact with true terrain.
- Data is **geographically true** (real DEM + OSM roads/buildings/suburb polygons; true north).
- Deploy is safe (rollback log + stash-safe discipline) and fast (compacted payload + progress).

**Weaknesses / debt to be aware of:**
- `viewer.js` is a **single ~4700-line file**. It's coherent but large; a future refactor into
  modules (render, sim, ui, overlays, ballistics) would help before major new gameplay.
- The web sim is a **separate, simpler implementation** from the Unity sim — they share the map JSON
  but NOT the combat/armour code. Depth systems (per-zone armour/pen, subsystem damage, drones/EW,
  weather-on-ballistics) exist in Unity but are **not** in the web demo. Decide per-feature whether
  web parity is wanted or whether the web stays a "tactical demo".
- Unit meshes are tiny at strategic zoom, so unit-level annotations (class letter, spot tags) only
  read when flown in close — expected, but worth noting for UX expectations.
- Mini-camera passes (portrait/POV) render the whole scene twice — fine now, but a perf watch item
  if unit counts grow.
